## 1. Executive Summary

**`v1.3.0`** extends the **`v1.2.1`** web platform with **Phase 10 (`T-1001`..`T-1008`)**, delivering a decoupled, native **C# `.NET 10 MAUI` Android Field Super-App (`Apex Moto` / `vn.motorcycledealer.mobile`)** designed specifically for showroom floor advisors, workshop bay technicians, and motorcycle riders on the go—requiring **zero breaking changes** to the `27`-table SQL Server schema, `18`-controller `/api/v1/*` REST contract, `48`-permission RBAC matrix, or `10`-event `/hubs/notifications` SignalR hub.

Built under strict inward Clean Architecture (`mobile/MotorcycleDealer.Mobile.sln`), the solution separates pure `net10.0` domain, security, API, SignalR, `SQLCipher`, and `CommunityToolkit.Mvvm` ViewModel logic (`MotorcycleDealer.Mobile.Core`, zero `<UseMaui>` dependency) from the compiled `net10.0-android` XAML `SourceGen` shell (`MotorcycleDealer.Mobile.App`) and pure `net10.0` xUnit test suite (`MotorcycleDealer.Mobile.UnitTests`).

### 2.2 Multi-Device Security Hardening & `SingleFlightTokenRefreshHandler` (`T-1002`)
- **Single-Flight `401` Refresh Serialization (`ADR-006`/`ADR-007`)**: `SingleFlightTokenRefreshHandler` guards `POST /api/v1/auth/refresh` with a singleton `SemaphoreSlim(1, 1)` double-check (`currentAccessToken != failedBearerToken`) over a dedicated handler-free `"AuthRefreshClient"`, cloning buffered requests cleanly so `10` simultaneous `401` responses trigger **exact `1`** token rotation (preventing `REFRESH_TOKEN_REUSE_DETECTED` family revocation).
- **Immediate Revocation & Multi-Device Logout Isolation**: Automatically invokes `ISessionResetCoordinator.ForceSignOutAsync()` on `403 ACCOUNT_LOCKED` / `STAFF_DEALER_UNASSIGNED`. `LogoutCoordinator` posts `LogoutRequest { RefreshToken, RevokeAllDevices = false }` by default so signing out of Android leaves the user's AngularJS Web SPA session intact (with optional `SignOutAllDevicesCommand` when explicitly requested).
- **Android Keystore & Transport Hardening**: Stores JWT/refresh tokens and the generated 256-bit `SQLCipher` passphrase in `SecureStorage.Default` (Android Keystore); enforces `android:allowBackup="false"` in `AndroidManifest.xml`; enforces HTTPS-only `<base-config cleartextTrafficPermitted="false" />` in `network_security_config.xml` with cleartext strictly limited to loopback/emulator hosts (`10.0.2.2`, `localhost`, `127.0.0.1`).

### 2.3 Encrypted `9`-Table `SQLCipher` WAL Offline Cache & `ADR-003`/`ADR-005` Online-Only Law (`T-1002`)
- **Encrypted On-Device Store (`MobileOfflineDb`)**: Uses `SQLitePCLRaw.bundle_e_sqlcipher` (`PRAGMA journal_mode=WAL;`) across **`9` local tables**:
  - *Public (preserved across logout)*: `CacheSyncState`, `CachedDealer`, `CachedMotorcycleModel`.
  - *Tenant/User-Scoped (`OwnerScopeKey = "{UserId}:{Role}:{DealerId ?? 'global'}"`, wiped on logout/`403`)*: `CachedCustomerVehicle`, `CachedLoyaltyWallet`, `CachedCustomerVoucher`, `CachedActiveAppointment`, `CachedReceiptSnapshot` (infinite-TTL offline receipts), and `OfflineMutationQueueItem`.
- **Strict Online-Only Financial & Concurrency Boundary**: `OfflineOutboxSyncService` strictly rejects offline queueing of `SalesOrders`, `ServiceInvoices`, `ServiceInvoiceLineItems`, `PointLedgerEntries`, `RowVersion` slot/test-drive reservations, and voucher redemptions (`ADR-003`, `ADR-005`). Only `NotificationRead`, `NotificationReadAll`, `VehicleMileageUpdate`, `ServiceReviewSubmit`, and `WarrantyClaimSubmit` enter the FIFO outbox (dropping cleanly on `409`/`422`).

### 2.4 Camera2 VIN/QR Scanner, Offline Vector QR Renderer & `10`-Event SignalR + Android Channels (`T-1003`, `T-1004`)
- **Camera2 VIN/QR Scanning & Pure C# Offline QR Display**: `CameraBarcodeScannerPage` (`ZXing.Net.Maui.Controls`) decodes 17-char ISO 3779 VIN chassis labels and `dealer://voucher/v1`, `dealer://booking/v1`, `dealer://receipt/v1` URIs (with instant manual input fallback for emulators). `QrCodeDisplayView` + `QrCodeMatrixEncoder` render crisp vector QR codes completely offline inside basement workshops.
- **`10`-Event SignalR & Native Android `NotificationChannel` Alerts**: `SignalRMobileService` subscribes to all `10` `/hubs/notifications` events with `[0, 2, 5, 10, 30]s` backoff, pauses in `Window.Stopped`, catches up via `GET /api/v1/notifications?sinceUtc=...` in `Window.Resumed`, and raises native `AndroidX.Core.App.NotificationCompat` alerts across `BookingAlerts`, `LoyaltyRewards`, and `WarrantyUpdates` channels (respecting Android 13+ `POST_NOTIFICATIONS`).
